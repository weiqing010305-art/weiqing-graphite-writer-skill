# 公众号写作规范

本文件是「写」的权威来源，排版无关。写作产出的 Markdown 将交给 `theme-graphite-minimal.md` 转成公众号 HTML，因此**结构必须规整**（`##` 章节、`>` 引言、`**加粗**`、`==高亮==` 等标记要写全），排版阶段才能正确映射。

## 一、平台规格

| 项 | 要求 |
|---|---|
| 篇幅 | 正文 1500–3000 字（用户指定则从其指定） |
| 结构 | 主标题 + 引言 + 多个二级小标题（`##`，建议 4–7 个）+ 升华式结尾 |
| 段落 | 短段落为主，每段 2–5 行（手机屏阅读） |
| 标点 | 全角中文标点（，。！？：；""''（）——…），代码/URL/英文专名内部保持半角 |
| 标题 | **不在正文里写 `#` 一级标题**——公众号标题填在平台标题栏，正文 `#` 会被排版阶段丢弃 |

## 二、标题钩子（决定打开率）

公众号标题 14–28 字最佳。常用类型：

| 类型 | 公式 | 示例结构 |
|---|---|---|
| 数字清单 | 「N 个 X，第 M 个让我 Y」 | 《3 个 AI 财报工具，第 2 个我用了半年》 |
| 反差结论 | 「我以为 A，结果 B」 | 《我以为 RAG 要靠大模型，结果卡在切分》 |
| 痛点直击 | 「X 总是 Y？问题出在 Z」 | 《估值模型总对不上？问题出在数据源》 |
| 身份+方法 | 「X 年 Y 岗位，我把 Z 做成了 W」 | |
| 悬念追问 | 「A 到底能不能 B？」 | |

**要求**：标题必须含**具体名词或数字**，不要空泛（避免「一些思考」「浅谈」）。提供 1 个主推 + 2 个备选。

## 三、正文结构（公众号深度长文范式）

```
【主标题】            ← 独立一行给出，不进正文
【开头钩子】           ← 3 行内抓住读者：矛盾/场景/反常识结论 → 写作 `>` 引言金句 或首段
【正文 · 4~7 个 ## 章节】
    每章 = 观点句（加粗）+ 展开论证（案例/数据/步骤）+ 收束句
    穿插：引用块 `>`、要点列表、对比表格
【升华式结尾】         ← 从具体事件上升到方法/认知层面，回扣开头
【CTA 转化引导】
```

**论证要求**：
- 每个观点至少配 **1 个具体例证**（数据、案例、亲历场景），不空谈。
- 数据引用须可核实，注明来源（如「据 XX 2025 年报」）；无法核实的一律不写。
- 把抽象概念落成读者能复述的一句话（可写成金句放进 `>` 引用块）。

**Markdown 标记规范**（排版阶段按语义映射，写的时候就要标对）：

| 想表达 | 写法 |
|---|---|
| 章节标题 | `## 标题`（自动编号 01/02…；末章结语自动 ∞） |
| 小节标题 | `### 标题` |
| 加粗强调 | `**文字**`（每段 ≤1 处，全文锚点级加粗 ≤5 处） |
| 核心概念高亮 | `==文字==` |
| 关键词下划线 | 不用手写，排版阶段会自动逐段标 |
| 金句 / 引语 | `> 金句` 独占一段 |
| 步骤 | `1. 2. 3.` 有序列表 |
| 并列要点 | `- 项` 无序列表 |
| 数据对比 | Markdown 表格 |
| 代码 / 命令 / Prompt | ` ``` 围栏 ``` ` 或行内 `` `code` `` |

## 四、CTA 转化引导（文末一处）

公众号默认 CTA（排版阶段会并入尾部签名区）：
> 如果你觉得今天这篇有收获，欢迎**点赞、在看、转发**三连，我们下篇见

可替换为更贴合内容的 CTA（如引导评论提问、引导看合集）。**全文只有一个 CTA**，不要中间到处求关注。

## 五、质量自检清单（交付前逐项打勾）

- [ ] 标题有具体名词/数字，非空泛表述；给了备选
- [ ] 开头 3 行内出现钩子，读者知道"这篇跟我有什么关系"
- [ ] 每个观点都有具体例证，无纯空谈段落
- [ ] 章节 4–7 个，层级只用 `##` / `###`
- [ ] 数据/引用可核实，来源已注明
- [ ] 结尾有升华 + 唯一一处 CTA
- [ ] CTA 与签名区各只有一处
- [ ] 字数落在目标区间
- [ ] 正文标点全角，代码/URL 除外
- [ ] 无违禁词、无绝对化用语

## 六、合规红线

**绝对化用语（禁用）**：最好、第一、唯一、最、顶、极、首个、全网第一、国家级、最佳、No.1。
→ 改写：用「我试过里比较顺手的一个」「据 XX 数据」「在 A 场景下表现突出」。

**金融/投资类额外注意**（涉及财经内容时）：
- 不得出现荐股、承诺收益、「稳赚」「保本」「必涨」等表述。
- 涉及个股/基金观点须标注「以上内容仅为个人学习记录，不构成任何投资建议」。
- 收益率、回测数据须说明区间与来源，不得只报好数字。

**其他禁用**：虚假测评、捏造个人经历、编造的对话或截图、无法核实的数据、"点击领取/免费送"类诱导。

## 七、配图建议

交付时按章节位置给出配图建议（3–6 处），每处写清：**放在哪一节 + 画面内容 + 建议比例**。
- 优先真实截图 / 数据图 / 流程示意图，避免通用图库风。
- 排版阶段用 Markdown `![说明](URL)` 占位，有说明文字才会生成图注组件；素材未定时写 `![](待补)` 并用居中占位板块。

## 八、交互约定

- 用户请求要素不全时（缺**主题**、**字数**、**风格**任一关键项），先确认补齐再动笔；风格可选：专业深度 / 轻松口语 / 测评对比 / 科普讲解。
- 用户说「直接写 / 不用问」时，按默认值执行：字数 2000 左右、专业深度风格、配图建议给 4 处，交付时说明所取默认值。
- 用户给的是**现成稿件**（不是要新写）时，跳过本文件的写作步骤，直接进入排版流程，不做内容改写。
