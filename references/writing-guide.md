# 公众号写作规范

仅在新写或获准润色时读取；纯排版不执行本文件的内容编辑规则。

## 写作默认值

未指定时采用约 2000 字、清楚专业的语气，面向普通公众号读者。长度随主题调整；用户指定优先。主题明确便直接写，不为字数、语气或配图数量单独追问。

标题放在 Markdown 的 `# 标题` 或 frontmatter title 中，排版时移出正文。新写给 1 个主标题和 2 个备选；标题明确说明对象和价值，不用缺乏依据的数字或悬念。14–28 字是参考范围，不是验收门槛。

## 结构与证据

开头尽快交代具体问题、场景或观点。一般长文可分 4–7 节，短文、访谈和叙事文章按内容组织，不强行补章节。结尾回扣主题或给出可行下一步，不必每篇升华。

每个重要观点配有用的例证、步骤或可解释的推理。数据、测评、引语和现实案例注明可追溯来源；时效性信息先查证，保留日期和链接。不编造个人经历、对话、截图、使用时长或来源。假设案例明确标成示例，不伪装成事实。查证失败时标为待核实或移除断言。

短段落便于手机阅读，但不用固定行数衡量。保留有用的细节，避免段段金句和反复强调。

## Markdown 交接

| 内容 | 标记 |
|---|---|
| 平台标题 | `# 标题` 或 frontmatter title |
| 章节 / 小节 | `##` / `###` |
| 加粗 / 高亮 / 下划线 | `**文字**` / `==文字==` / `++文字++` |
| 引语 | `>`，注明真实出处 |
| 步骤 / 要点 | 有序 / 无序列表 |
| 数据对比 | 表格，保留单位、时间和全部字段 |
| 代码、命令、Prompt | 围栏代码块；短标识用行内代码 |
| 图片 / 链接 | `![真实说明](地址)` / `[来源](地址)` |

标记按语义添加，不必用遍所有组件。下划线可由排版阶段按需增加。代码、数字、英文专名及 URL 不进行全角替换；中文叙述使用“弯引号”和中文标点。

## CTA、署名与配图

新写默认最多一处贴合内容的 CTA，例如邀请读者分享实践经验。用户不需要时省略；不机械插入点赞、在看、转发三连。署名与简介必须来自用户，未知时省略；用户要求保留占位才使用占位。

按内容需要给出配图建议：位置、画面与比例，通常 0–4 处即可。优先真实截图、数据图、流程图。未提供素材时列出待补说明，不生成失效图片地址。含图最终交付须通过图片加载和公众号复制粘贴实测；未验证素材不能算完成。建议与待补素材分开列出。

## 发布前自检

- 标题与正文相符，开头交代阅读价值，结尾不重复全文。
- 核心观点有支撑；事实、日期、数字、引语及来源可核实。
- 没有捏造作者经历、身份、案例和测评。
- 篇幅与用户要求相符；章节按内容组织；CTA 不重复。
- 代码和链接未损坏，真实配图与占位区分明确。
- 纯排版未执行内容改写；润色没有超出授权程度。

## 需要具体判断的表述

检查缺乏依据的排他性宣传、收益承诺和误导性营销，按语境修正，不把“最、第一、唯一”等字词一概当作违禁词。例如“第一步”是正常步骤表述。需要判断广告或行业规定时查阅适用的现行规则，不把本清单当作法律结论。

财经内容不承诺收益或把假设回测写成真实业绩；报告区间、来源、成本和局限。个股或产品分析中按内容与用户用途说明边界，不能靠一句免责声明代替准确性。仅做排版时，风险提示放在交付说明，未经授权不插入原文。
